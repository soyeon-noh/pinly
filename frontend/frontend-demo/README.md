# pinly 캔버스 스파이크 (frontend-demo)

캔버스 + 그리기 툴의 **구현 난이도와 성능 한계를 실측**하기 위한 일회성 프로토타입.
제품 코드가 아니라 **측정 장치**다. 결론만 본체 프론트엔드 레포로 옮기고 이 디렉터리는 버린다.

```bash
npm --prefix frontend/frontend-demo install
npm --prefix frontend/frontend-demo run dev   # http://localhost:5174
```

## 구현 범위 (약 715줄)

| 기능 | 상태 | 비고 |
|---|---|---|
| Stage 팬/줌 (포인터 기준, 트랙패드 팬) | O | Figma 규칙: 두 손가락=팬, ⌘/Ctrl+휠=줌 |
| 툴바 (선택/이동/댓글/텍스트/그리기/선삭제) + 단축키 | O | `V H C T P E` |
| 자유선 그리기 → `drawing` 요소 | O | Konva `Line` + `tension` |
| 지우개 = 선 객체 삭제 | O | 스키마 §4-3 그대로 |
| 선택·이동·리사이즈·회전 (Transformer) | O | |
| 텍스트 추가 + DOM 인라인 편집 | O | Konva 위에 `textarea` 오버레이 |
| 이미지 첨부 (로컬 파일 / 샘플 원고 생성) | O | 데모는 objectURL, 실제는 presigned URL |
| 핀(코멘트) DOM 오버레이 + 스레드 + 답글 | O | Konva 아님. transform 으로 좌표만 동기화 |
| 피드백 상태 (수정 대기/확인 대기/확인됨) | O | 로그 패널 ↔ 캔버스 양방향 |

| `docs/canvas-schema.md` JSONB 직렬화 + 크기 계측 | O | 저장 페이로드 그대로 |
| 부하 테스트 + FPS/노드 수/드로우 타임 | O | `window.__pinly.bench()` |

### 일부러 뺀 것 (= 남은 일감)
S3 presigned 업로드, 저장/로드 API 연동, 실시간 동기화, 모바일·터치·스타일러스,
색상/굵기 팔레트, 레이어 패널, 이미지 자르기, 다중 선택, 복사/붙여넣기,
텍스트 서식 UI, 접근성, 오프라인 복구.

## 실측 결과 (M-series Mac, Chromium, 1400×850)

`window.__pinly.bench()` — 선 1개 = 41점 기준.

| 선 개수 | 좌표 수 | `layer.draw()` | 씬만 (`drawScene`) | JSONB | `JSON.stringify` |
|---|---|---|---|---|---|
| 1,000 | 41,000 | 15~35 ms | 8~16 ms | 1.7 MB | 20 ms |
| 3,000 | 123,000 | 20~110 ms | 7~51 ms | 5.1 MB | 26 ms |
| 6,000 | 246,000 | 200 ms+ | 85~130 ms | **10.2 MB** | 94 ms |

측정값 편차가 큰 것은 브라우저 스로틀링 탓. **추세만 본다.**

### 여기서 나온 사실

1. **히트 그래프가 렌더 비용의 절반.** `draw()` 22.6 ms 중 `drawScene()` 은 10.6 ms.
   → 팬/줌 중에는 드로잉 레이어를 `listening(false)`, 정지 시 복구. 또는 레이어 분리.
2. **`tension: 0.4` 가 렌더 비용 +30%** (16.1 → 22.6 ms @3,000선).
   → 그릴 때만 곡선 보정, 확정 후에는 점 단순화 + `tension: 0` 검토.
3. **좌표 반올림만으로 JSONB 67% 감소.** 10.2 MB → 3.4 MB (정수 반올림).
   캔버스 좌표에 소수점 이하는 의미가 없다. **스키마 규칙으로 못박아야 한다.**
   (RDP 단순화는 이 데모의 난수 데이터엔 효과가 적지만, 실제 필압 스트로크에는 더 크게 먹힌다.)
4. **문서 통째 저장은 그대로 못 쓴다.** 6,000선에서 `JSON.stringify` 만 94 ms —
   메인 스레드 블로킹 + 10 MB PUT. 자동저장은 디바운스 + 변경분 전송이 필요.
5. **아트보드 기본값 1920×1080 이 웹툰 원고와 안 맞는다.** 세로 원고(1200×4000+)를 넣으면
   아트보드 밖으로 넘친다. `stage.width/height` 를 첫 이미지에 맞춰 잡거나 가변으로.
6. **핀 DOM 오버레이는 저렴하고 정확하다.** 팬/줌 중 좌표 동기화에 성능 문제 없음.
   Figma 방식 채택 판단은 유효.
7. 그리는 동안 `setState` 로 React 전체를 재렌더하면 선이 길어질수록 느려진다.
   → 진행 중 스트로크는 React 밖에서 Konva 노드에 직접 `points()` 로 붙여야 한다. (데모는 일부러 순진하게 구현해 비용을 드러냄)
